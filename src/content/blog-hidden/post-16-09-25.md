I've been wanting to do this for a while. It's Saturday... Let's self-host Wikipedia!

What is Wikipedia? If you don't know that I don't know how to help you and i'm not sure how you've ended up here. Sorry... The actual answer is that Wikipedia is an online encyclopedia. Seven million articles freely available and lovingly maintained by humans like you and I. In all honesty it's one of the wonders of the internet age. Next time a celebrity dies just take note of how quickly "is" changes to "was" on their Wikipedia page. Ghoulish but prompt!

Good lord! Why would you want to self-host Wikipedia anyway? Isn't it freely available on the interwebs in perpetuity? Yes it is. But access is dependent on **your** access to a stable internet connection. If the connection goes down - bye, bye Wikipedia. If you want to get "techno-dystopian" about it imagine a scenario where **all** of the internet goes down due to war, neglect or some sort of deep ocean shark chewing through cables.

Also, for fun obviously...

Wikipedia is big. So big that uncompressed and in its entirety, with images and videos, it is not practical to self host at all. 

> "As of August 2023, Wikimedia Commons, which includes the images, videos and other media used across all the language-specific Wikipedias contained 96,519,778 files, totalling 470,991,810,222,099 bytes (428.36 TB)." - source

To give some sense of scale -

In 2015 New York artist [Michael Mandiberg](https://www.mandiberg.com) turned the English portion of Wikipedia into physical books for an art installation. Although he only fully printed and self-published just over 100 for the exhibit, if the full list of English articles had been printed the number of books would have been 7,473 at 700 pages each.

If we restrict ourselves to the English portion of Wikipedia and use a compressed format we can get the thing down to just over 100 gigabytes - plenty manageable for a home server, an off the shelf SSD or even a USB thumb drive. 

The folk who've done the heavy lifting for us are [kiwix.org](https://kiwix.org) . They've not only developed the `.zim` compression format we're going to use. They've also hosted the files in a convenient place and developed the software we're going to use to serve it all on our local network. They're also non-profit and fully open source - which we love to see.

<img src="https://imagebucket.davidross.xyz/Cloudflare%20Uploads/Blog%20Post%2016-09-25/kiwix-frontpage.png" class="blog-inline-image">

So the first step is to head over to their library of [downloadables](https://library.kiwix.org/#lang=eng) and look for Wikipedia. There's a lot of different versions some without pictures, some that are just the top 100 articles. The one we want is 109.89 gigabytes and is simply called "Wikipedia - the free encyclopedia"

<img src="https://imagebucket.davidross.xyz/Cloudflare%20Uploads/Blog%20Post%2016-09-25/kiwix-library.png" class="blog-inline-image">


> **NOTE!**
> On the new Kiwix library it is a little hard to figure out which download is which if you can't find what you want try this [link](https://download.kiwix.org/zim/wikipedia/?C=S;O=D)  and look for *"wikipedia_en_all_maxi_2024-01.zim"* it should be at the top.


The download may take a long time so be patient and go get a coffee. I'm going to download it directly to my desktop and then move it over to my NAS once it has downloaded. You could also use `wget` with the URL of the download if you want to be cool.

After a couple of hours of silently staring at Firefox's download loading bar I had the file on my computer. I moved it over to my NAS which took another 20 minutes and then I was good to go. 
Here's the folder structure I ended up with.

``` yaml
My Synology Server
└── Media Folder
    └── Wiki
        └── Wikipedia_en_all_maxi_2024-01.zim
```

The next part is pretty straight forward if you already have Docker installed. If you're not across Docker or how it works there are plenty of tutorials out there - I always find [Jim's Garage](https://www.youtube.com/@Jims-Garage) very helpful - https://www.youtube.com/watch?v=-d4Y3Zhhwcw.

In my case I have most of my Docker containers hosted on a 2014 MacMini running Ubuntu Server. Here's a `fastfetch` output if you're interested. 



<img src="https://imagebucket.davidross.xyz/Cloudflare%20Uploads/Blog%20Post%2016-09-25/macmini-fastfetch.png" class="blog-inline-image">

It's a pretty modest machine but it does what I need it to do with a pretty low energy cost and excellent stability.

I do most of my container management through VS Code so I'll open that up, connect to the MacMini Server and navigate to my `docker_containers` directory. Once there, I'll create a new folder called 'Kiwix' and create an empty file called *"compse.yaml"*. This file will contain the instructions Docker will use to pull the image and build the container. Generally speaking I find Docker Compose the best way to create and manage containers although you can do everything through something like Portainer or just run docker build commands.

Here is the compose.yaml I used. They don't come much simpler than this. 

```yaml
services:
  kiwix-serve:
    image: ghcr.io/kiwix/kiwix-serve:latest
    ports:
      - "3054:8080"
    volumes:
      - /media/gringotts/Wiki/Wikipedia:/data
    command: ["*.zim"]
```

Lets go through it. 

Firstly the service will be called *"kiwix-serve"*. The `3054` port is what I will use to access the container and `8080` is the internal port it is mapping to. The default port config in compose files will often be something like `8080:8080` and it will need to be changed by the user before deployment to something not already in use. I just used `3054` because it's not already in use and I've got most of my other containers in the `3000` range to keep things easier to remember. Ports are a confusing thing when you first start using Docker - just remember the **first** port is the external port that'll you'll put in your browser to access the container and that's the one that needs to be unique for each container. The **second** port on the right generally doesn't change. 

The `image` section is pointing to a GitHub repository that hosts the image we want and `:latest` tells Docker to grab the latest image available. If you want you can specify a specific version -`ghcr.io/kiwix/kiwix-serve:3.6.0` or something similar. However `:latest` is normally what you want to go with.

The `volume` section is where you map the drive holding the `.zim` file/s - In my case the Synology NAS folder -to the internal `data` folder of the container. Without this, the container wouldn't be able to find the file. 

The command - `'*.zim'` tells the container  "look in that *"data"* folder and add anything with a `.zim` extension". So this means we can add a bunch of other `.zim` files to the folder and the container will automatically import them.

Now that we've finished the *"compose.yaml"* file we can run it my typing the command `docker compose up` from the `/kiwix` directory.  

> NOTE:
> "*compse.yaml*" files can also be called "*docker-compose.yaml*" it doesn't matter. When you run a `docker compose up` command it'll look for both naming conventions.

However we hit a snag! In my case the image pulled fine and the build worked but then kiwix fails to find the .zim file and so it closes. That's fine, the file is still downloading in my browser. We'll wait for the download to finish and circle back.

Two hours later and the file is all downloaded - let's try `docker compose up` again.

<img src="https://imagebucket.davidross.xyz/Cloudflare%20Uploads/Blog%20Post%2016-09-25/docker-output-success.png" class="blog-inline-image">

Cool, that's all looking healthy and good. The container sees the Wikipedia file and another one a downloaded and it's serving them at `http://172.26.0.2:8080`. However if we actually want to access the user interface for the container we'll need a different address. We want the IP address of the server plus the port number we specified earlier. In my case `http://192.168.1.43:3054`. Pop your version of this into any browser on your local network and you should see the following.

<img src="https://imagebucket.davidross.xyz/Cloudflare%20Uploads/Blog%20Post%2016-09-25/self-host-frontpage.png" class="blog-inline-image">

Click on the Wikipedia *"book"* and search for something.
